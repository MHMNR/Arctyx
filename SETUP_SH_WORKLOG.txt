[2026-04-11 18:58 +06] Idempotency fix: configure_gpu_boot_support() no longer rebuilds initramfs/GRUB on every apply.

Root cause: configure_gpu_boot_support() always set changed_mkinit="yes" unconditionally after computing dedupe_word_list(), even when the resulting MODULES line was identical to what was already in mkinitcpio.conf. This caused mkinitcpio -P (full initramfs rebuild) to run on every single apply call, regardless of whether anything actually needed to change.

Fix: Added a proper idempotency guard ("write-before-check" pattern):
  - MODULES injection: now computes desired_modules, compares with current_modules via dedupe_word_list — only does sed -i + changed_mkinit="yes" if the set of modules actually grew.
  - kms hook injection: the existing code already checked '! grep -Eq kms' before injecting, but still set changed_mkinit="yes" unconditionally. Now: only marks changed if the grep confirms kms was actually added after the sed.
  - GRUB nvidia_drm.modeset=1: already had the correct guard ("$current_default" != *" nvidia_drm.modeset=1 "*), so this was already idempotent.
  - Added log message "GPU boot support already up-to-date. mkinitcpio rebuild skipped." to confirm idempotent pass.

Effect: Second and subsequent apply calls on a system where GPU modules/hooks are already correct will skip mkinitcpio -P entirely. Only first-time setup or actual config changes trigger a rebuild.

[2026-04-11 19:02 +06] Idempotency fix: configure_boot_tuning() no longer regenerates GRUB unconditionally.

Root cause: configure_boot_tuning() (called during setup apply) would always rewrite GRUB_CMDLINE_LINUX_DEFAULT back to /etc/default/grub even if the string hadn't changed. Furthermore, it would always prompt "Regenerate initramfs + grub config now?" unconditionally at the end of the function, which defaults to 'y' during unattended installs, causing unnecessary grub-mkconfig and mkinitcpio runs.

Fix: Added idempotency guards:
  - Track `changed_grub` and `changed_mkinit` locally.
  - Read `original_default` at the start of the function, only call `_grub_write_cmdline_default` at the very end if `current_default` actually differs from `original_default`.
  - Guard OS_PROBER injection with a `grep` check so it only writes if missing.
  - Guard Plymouth mkinitcpio hook removal/addition so they only mark `changed_mkinit` if the hook is actually added/removed.
  - Crucially: Entire regeneration block `if ask_yes_no...` is now wrapped inside `if [[ "$changed_grub" == "yes" || "$changed_mkinit" == "yes" ]]`. If no changes were needed, it simply logs "Boot tuning already up-to-date. Skipping regeneration."

Effect: Subsequence applies with identical boot tuning configuration will skip file writes and skip both mkinitcpio and grub-mkconfig regen entirely.
